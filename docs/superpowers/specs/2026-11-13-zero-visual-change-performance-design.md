# 零视觉变化性能优化设计与解决方案

> 文档性质：性能改造设计、等价条件与验收依据
> 编制日期：2026-11-13
> 分支：`perf/zero-visual-change`
> 适用仓库：`dsh-claude-style-lite`
> 依据：当前 `packages/client/src`、`packages/engine/src`、`packages/contracts/src` 与测试源码
> 状态：方案与修改计划已完成，尚未修改产品源码

---

## 0. 目标与硬约束

本次改造只减少重复执行、重复测量与无效后台工作。界面、样式、文案、DOM 结构、属性、事件顺序、动画参数、动画起始时刻、动效持续时间与首屏呈现都必须保持不变。

硬约束如下：

1. 不修改任何 CSS 文件、设计令牌、动画名称、动画时长、缓动曲线、关键帧、`will-change`、`mask-image`、`content-visibility` 与 `contain-intrinsic-size`。
2. 不修改可见 DOM 的顺序、类名、属性、文本、焦点、选中项、滚动位置与无障碍名称。
3. 不改变调度帧的读取阶段、滚动阶段、写入阶段顺序，也不改变各功能句柄在 `FEATURES` 中的顺序。
4. 不改变既有延迟：`WORD_LOCK_MS`、等待行 250 毫秒刷新、10 秒超时徽章、加载器换场周期、侧栏展开与收起延迟、通知轮询周期、首页用量轮询周期。
5. 不修改 `lib/`。产品源码改动后统一通过 `npm run build` 生成构建产物。
6. 源文件接近 750 行停线时先按职责拆分，再增加逻辑。当前 `account/footer-mirror.ts` 为 745 行，必须先抽出固定层测量模块。
7. 每个任务只提交一个逻辑改动，提交标题与正文使用中文，提交前缀使用约定式前缀。
8. 缓存必须带明确失效来源。找不到完整失效来源的重复计算不进入本次改造。
9. 任何测试不得使用生产环境假实现、静默回退或仅用于通过测试的分支。

## 1. 收益排序

排序依据是默认开启路径上每帧、每次指针移动或每次键入所减少的工作量。这里的“收益”是静态调用路径判断，不是实测帧耗时；具体数值由计划中的测量任务给出。

| 排名 | 改造项 | 默认开启 | 高频路径 | 预计收益 | 等价条件 |
| --- | --- | --- | --- | --- | --- |
| 1 | 等待行拆开时钟刷新与业务同步，并在正文批次中停跑 | 是 | 每个流式调度帧、每 250 毫秒 | 很高 | 秒数、措辞锁、超时徽章、尾部属性与宿主发布时机的可见结果不变 |
| 2 | 页面级功能在仅正文变化的批次中停跑 | 是 | 每个正文流式调度帧 | 高 | 每个功能已有覆盖正文变化的订阅，或有明确测试证明正文批次不影响其输入 |
| 3 | 页脚镜像缓存固定层判定 | 是 | 每个完整调度帧 | 高 | 页脚子树属性、类名、角色与结构变化都能使缓存失效 |
| 4 | 尺寸观察器按被观察元素路由条目 | 是 | 每次尺寸批次 | 高 | 回调顺序、每订阅一次批次、初次尺寸报告与 `afterHost` 顺序不变 |
| 5 | 消息折叠改为一个共享尺寸订阅 | 是 | 每次用户气泡尺寸变化 | 高 | 每个气泡的判定失效、触摸集合与重建开关行为不变 |
| 6 | 问候语只查询标题组并缓存 | 是 | 每个完整调度帧 | 中高 | 首页问候轮换、宿主改写恢复、布局切换与离页恢复不变 |
| 7 | 首页概览数据按输入记忆化 | 是 | 每次首页存储通知与重渲染 | 中高 | 数值、热力格、模型图、范围切换与书本选择不变 |
| 8 | 搜索静态来源行缓存 | 是 | 每次键入 | 中高 | 各分区顺序、结果数量、摘要与选中项不变 |
| 9 | 归档列表缓存排序与签名 | 是 | 已归档分段的每个调度帧 | 中 | 排序、分页游标、行内容与归档变更响应不变 |
| 10 | 过程摘要缓存头部样式读数 | 是 | 每个被触及过程组 | 中 | 全文与紧凑措辞的判定结果不变 |
| 11 | 后台轮询等待可见页面 | 是 | 通知每 1500 毫秒、首页用量每 800 毫秒 | 中 | 可见窗口中的轮询周期、回到前台补读与通知点击路由不变 |
| 12 | 指针活动合并到一帧 | 是 | 每次 `pointermove` | 中 | 吉祥物在同一帧内收到活动，睡眠与唤醒判定不变 |
| 13 | 侧栏预览指针判定合并到一帧 | 是 | 展开状态下的每次 `pointermove` | 中 | 120 毫秒展开、300 毫秒收起与“指针在栏内”判定不变 |
| 14 | 调度器维护事件钩子索引 | 是 | 每次按键、按下、聚焦、输入 | 中低 | 钩子调用顺序、异常隔离、退役与动态安装不变 |
| 15 | 非 Claude 品牌下等待加载器使用虚拟状态（需单独确认） | 是 | 每个等待行、每 10 秒换场 | 低 | 切回 Claude 品牌时可见车道、点数与动画相位不变；品牌切换恰好落在 300 毫秒换场窗口内时，重建换场使用当前几何，存在需确认的视觉边界 |

`chat-follow`、`turnNav`、`composer` 不进入第 2 项。它们的输入可能在仅正文变化的批次中出现，当前没有完整覆盖这些变化的独立订阅。

## 2. 逐项解决方案

### 2.1 等待行拆开时钟刷新与业务同步

**现状证据**

- `packages/client/src/features/chat-wait/chat-wait.ts:62` 定义 250 毫秒步长。
- `chat-wait.ts:246-315` 的 `syncRow` 每此都读取宿主运行行、会话、聊天目标快照、开放回合、活动词、偏好、措辞锁、时钟与超时徽章。
- `chat-wait.ts:360-415` 的 `syncLines` 每次遍历全部运行行；250 毫秒定时器与每个调度帧都会走到这里。
- `chat-wait.ts:415` 的句柄没有 `skipOnContentOnly`，所以每个正文流式批次仍会执行完整同步。
- `packages/client/src/shared/format.ts:14-23` 把时钟文本取整到秒，250 毫秒周期内最多三次写入相同文本。

**解决方案**

1. 给 `WaitLine` 增加四个不可见状态：回合开始时刻、等待开始时刻、措辞锁结束时刻、是否已订阅宿主目标。
2. 250 毫秒定时器改为只执行轻量刷新：读取尾部判定、写时钟文本、写超时徽章。
3. 任一运行行没有宿主目标订阅时，轻量刷新回退到完整 `syncLines`，保持没有 `target.subscribe` 的宿主行为。
4. 宿主目标发布继续通过 `target.subscribe(scheduleSync)` 触发局部同步。
5. `runningRows` 增加 `onChange`，运行行增删与替换直接调用 `scheduleSync`。
6. 在以上订阅完整后为 `ui.chatWait` 增加 `skipOnContentOnly: true`。

**等价依据**

- 秒数文本仍按原 250 毫秒节奏写入，取整规则不变。
- 措辞锁到期时，轻量刷新发现 `now >= wordUntil` 后执行完整同步，措辞更换仍落在原锁结束时。
- 超时徽章在轻量刷新中按原 `WAIT_OVERTIME_MS` 判定，出现与消失时刻不变。
- 尾部属性仍由原 `readTails` 与 `writeTails` 在同一帧完成。
- 没有宿主目标订阅的路径保留 250 毫秒完整同步，不缩短功能覆盖。

### 2.2 页面级功能在仅正文变化的批次中停跑

**现状证据**

- `packages/engine/src/scheduler.ts:320-330` 只把批次是否完全位于对话滚动容器内作为 `contentOnly`。
- `scheduler.ts:350-384` 只跳过显式声明 `skipOnContentOnly` 的句柄。
- 当前 48 个功能中只有 11 个句柄声明了跳过。
- 首页、侧栏、搜索、设置、权限、问题卡、吉祥物与首页水波都位于对话正文之外。

**解决方案**

为以下句柄增加 `skipOnContentOnly: true`：

| 功能 | 句柄文件 | 正文批次不影响其输入的原因 |
| --- | --- | --- |
| 首页水波 | `features/home-ripple/home-ripple.ts` | 只在首页英雄区域挂载，正文流式批次不触及英雄根 |
| 吉祥物 | `features/mascot/mascot.ts` | 状态来自宿主会话状态与聊天快照订阅，站位在输入区与页面层 |
| 英雄菜单 | `features/hero-menu/hero-menu.ts` | 触发器和菜单都在输入区与页面弹层 |
| 权限 | `features/permissions/permissions.ts` | 分段与卡片位于输入区，正文文本不构成其输入 |
| 问题卡 | `features/question-card/question-card.ts` | 卡片位于输入区 |
| 工作区 | `features/workspace/workspace-view.ts` | 分段、归档列表与搜索都在侧栏 |
| 搜索 | `features/search/search.ts` | 搜索面板在页面层，来源来自宿主快照 |
| 设置导航 | `features/settings/settings-nav.ts` | 设置页不在对话正文内 |
| 上下文仪表环 | `features/context-stats/meter-ring.ts` | 仪表环位于输入区；宿主写入仪表时不属于正文批次 |

`homeLayout` 在第 6 项建立标题组订阅后再加入清单。`chatWait` 在第 1 项建立订阅后加入清单。

**等价依据**

正文流式批次的变化节点全部位于对话滚动容器内。上述功能的读取目标在容器外，且各功能已有的偏好、宿主快照、尺寸或变更订阅覆盖容器外变化。逐功能回归用例必须覆盖开关切换、挂载、卸载与页面切换。

### 2.3 页脚镜像缓存固定层判定

**现状证据**

- `packages/client/src/features/account/footer-mirror.ts:143-149` 展开每个页脚条目的全部后代。
- `footer-mirror.ts:198-215` 对每个后代调用 `window.getComputedStyle(el).position`。
- `footer-mirror.ts:178-180` 的 `isFixedPanel` 每次读取计算样式。
- 该文件已有 745 行，不能继续增加逻辑。

**解决方案**

1. 新建 `features/account/footer-fixed.ts`，职责是“页脚节点是否固定层”的读取、缓存与失效。
2. 缓存使用可替换的 `WeakMap<Element, boolean>`。失效时替换整个映射，旧条目由垃圾回收处理。
3. 在页脚根上建立一个观察器，监听 `childList`、`subtree`、`attributes`，属性过滤为 `class`、`style`、`role`、`open`、`aria-expanded`、`aria-hidden`。
4. 观察器收到任一记录时替换缓存；下一次 `measure` 只重新读取未命中节点。
5. `footer-mirror.ts` 调用新模块的 `measureFixedPanels(entries)`，保留原 `fixed` 与 `measured` 集合语义。
6. 新模块提供 `stop()`，由镜像的 `stop()` 调用。

**等价依据**

被缓存的值只由节点自身及其祖先的样式、类名与角色决定。上述属性与结构变化都会使缓存失效。主题切换不改变 `position` 的计算规则，页面缩放不改变固定定位语义。宿主在读取阶段之后挂载的新节点不在缓存中，仍按原路径单独读取。

### 2.4 尺寸观察器按被观察元素路由条目

**现状证据**

- `packages/engine/src/bus.ts:553-582` 每个尺寸批次先复制订阅数组，再为每个订阅读取全部条目并执行 `filter`。
- `bus.ts:591-628` 每个订阅保存独立目标数组与集合。
- 一次批次有 N 个目标、M 个订阅时，条目筛选次数为 N×M。

**解决方案**

1. `SizeRegistry` 增加 `routes: Map<Element, Set<SizeSubscription>>`。
2. 订阅创建时把订阅加入每个目标的集合；取消订阅时逐一移除。
3. 观察器回调先遍历本批条目，把条目放入“订阅到条目数组”的映射；随后按 `registry.subscriptions` 的稳定顺序派发。
4. 用 `Set<SizeSubscription>` 判断订阅是否仍然有效，去掉 `subscriptions.includes()` 的数组扫描。
5. 增加 `observeSizes(callback, options)`，返回 `{ add, delete, stop }`，供目标集合动态变化的功能使用。
6. `observeSize` 保留现有签名，内部委托给 `observeSizes`，保证既有调用方不变。

**等价依据**

派发顺序仍按订阅创建顺序。每个订阅每次批次最多收到一次回调，且只收到自身目标条目。`afterHost` 重建观察器、重新观察全部元素与初次尺寸报告的语义保持。新增目标导致的初次报告仍按原生 `ResizeObserver` 语义送达。

### 2.5 消息折叠改为一个共享尺寸订阅

**现状证据**

- `packages/client/src/features/chat-fold/message-fold.ts:33` 为每个气泡保存一个停止函数。
- `message-fold.ts:112-118` 为每个气泡调用一次 `observeSize`。
- 气泡数量增加时，订阅数量同步增加，尺寸批次进入第 2.4 项的 N×M 路径。

**解决方案**

1. 用 `observeSizes` 建立一个共享订阅。
2. 用 `WeakSet<Element>` 记录已观察气泡，避免重复添加。
3. 批次回调遍历条目，对每个气泡执行原有三件事：删除旧判定、加入 `touched`、请求调度。
4. `release(bubble)` 调用共享订阅的 `delete(bubble)`，保留删除判定与开关的逻辑。
5. 功能停止时调用 `stop()`，清空观察集合。

**等价依据**

每个气泡尺寸变化仍使该气泡的旧判定失效并请求一次调度。共享订阅只合并观察器与条目过滤，不合并或延迟回调。原有 `requestPass` 合并机制继续负责同帧去重。

### 2.6 问候语只查询标题组并缓存

**现状证据**

- `packages/client/src/features/home/greeting-copy.ts:30` 每次完整调度帧执行 `document.querySelectorAll('[data-dsh-claude-part~="hero-title-group"]')`。
- `packages/client/src/features/home/home-layout.ts:194-219` 每个完整调度帧调用 `greeting.sync(hero)`。
- 会话页上 `hero` 为假，仍然执行全文档查询。

**解决方案**

1. `createGreetingCopy` 接收 `requestPass` 回调。
2. 用 `observeMarker<HTMLElement>('[data-dsh-claude-part~="hero-title-group"]')` 维护标题组集合，替代每次全文档查询。
3. 标题组的增删、标记属性变化与类名变化触发 `requestPass`。
4. 非英雄页且 `replaced` 中没有仍连接的节点时直接返回。
5. 首页布局卸载时调用 `greeting.stop()` 释放标记订阅。
6. 标题组订阅建立后，为 `homeLayout` 增加 `skipOnContentOnly: true`。

**等价依据**

标题组集合由与 `querySelectorAll` 相同的选择器维护。属性变化由 `observeMarker` 的标记属性过滤覆盖，节点替换由子节点变化覆盖。宿主改写标题文本后，原 `replaced` 恢复逻辑保持不变。离页时仍按原逻辑保留宿主原文。

### 2.7 首页概览数据按输入记忆化

**现状证据**

- `packages/client/src/features/home/home-layout.ts:88-107` 每次 `HomeUsagePanel` 渲染都调用 `homePanelData`。
- `home-figures.ts:260-397` 每次重算窗口汇总、按日数据、热力格、模型列表与 30 天模型数据。
- `home-layout.ts:76-82` 的存储订阅会使整个面板重渲染。

**解决方案**

1. 在 `home-figures.ts` 增加单条目记忆化工厂 `createHomePanelMemo()`。
2. 键由 `state.value` 的对象身份、`listed` 的对象身份、`range` 与 `bookPick` 组成。
3. 键全部相同则返回上一次结果；任一不同则重新调用 `homePanelData`。
4. `HomeUsagePanel` 用 `React.useRef(createHomePanelMemo())` 保持工厂生命周期，并在渲染中调用。
5. 组件卸载时无需额外清理，单条目缓存不持有页面节点。

**等价依据**

`homePanelData` 的输入只有四个参数。状态中的 `computing`、`error`、`loading` 不参与数据计算，继续由 JSX 直接读取。新报告与新列表摘要使用新对象身份，必然触发重算。返回对象按只读使用，复用不会改变视图输出。

### 2.8 搜索静态来源行缓存

**现状证据**

- `packages/client/src/features/search/sources.ts:103-118` 每次查询都重建可打开会话列表并排序。
- `sources.ts:196-236` 每次查询都重建项目行与插件行。
- `sources.ts:278-330` 每次查询都重建技能行、快捷键行与动作行。
- `packages/client/src/features/search/search.ts:177-183` 每次输入都调用 `render()`。
- `search.ts:385-410` 每次渲染清空列表并重建全部行。

**解决方案**

1. 为静态来源建立按宿主快照身份失效的缓存。
2. 可打开会话缓存键为会话列表快照、工作区列表快照与当前会话标识。
3. 项目行缓存键为工作区列表快照与 `hostUiWorkspace` 服务。
4. 插件行缓存键为插件数组身份与语言。
5. 技能行缓存键为技能数组身份、技能会话标识与宿主绑定。
6. 快捷键行缓存键为两个快捷键目录快照。
7. 动作行缓存键为语言、插件导航服务与设置槽位存在性。
8. `sections` 仍按查询执行标题会话过滤、内容命中合并、评分、截断与分区组装。
9. 每次打开搜索面板清空缓存，保持现有 `open()` 的重新读取语义。

**等价依据**

缓存的都是与查询无关的行模型与来源数组。查询过滤、内容命中、排序评分、截断与 `run` 闭包仍按当前查询生成。面板每次打开清空缓存，与现有“打开时重新读取插件与技能”一致。结果分区顺序与限制常量不变。

### 2.9 归档列表缓存排序与签名

**现状证据**

- `packages/client/src/features/workspace/archived-list.ts:164-181` 每次同步都调用 `archivedOrder` 并对当前窗口执行 `JSON.stringify`。
- `archived-list.ts:423-430` 已归档分段挂载时，每个调度帧都会调用 `sync()`。

**解决方案**

1. 在列表实例中保存上一次读取的输入身份：工作区列表快照、会话列表快照、当前会话标识。
2. 三者未变时复用上一次 `order` 与 `byId`。
3. `cursor` 未变时复用签名；游标变化时只重建签名，不重新排序。
4. 任一快照或当前会话变化时重新执行 `archivedOrder`。
5. 卸载时清空缓存，保持重新挂载从第一页开始。

**等价依据**

排序只依赖归档标识、会话摘要与当前会话。快照身份变化覆盖宿主发布新列表；摘要对象按宿主快照只读约定不会原地改写。游标属于签名输入的一部分，追加一页仍会触发渲染。

### 2.10 过程摘要缓存头部样式读数

**现状证据**

- `packages/client/src/features/chat-fold/process-summary.ts:220-239` 的 `availableWidth` 每次执行两次 `getComputedStyle`，并读取父容器宽度、头部子元素矩形。
- `process-summary.ts:352-361` 已经有共享摘要尺寸订阅。
- `process-summary.ts:415-430` 每个被触及组在读取阶段调用 `formOf`，进而调用 `availableWidth`。

**解决方案**

1. 新建 `features/chat-fold/summary-width.ts`，职责是缓存头部与父容器的间距、内边距与边框宽度。
2. 缓存内容包括头部 `columnGap`、左右内边距、左右边框与父容器左右内边距。
3. 用共享 `observeSizes` 观察已总结头部及其父容器；任一尺寸变化使该头部的样式缓存失效。
4. 字体加载完成、页面缩放变化与文案变化使全部缓存失效。
5. `availableWidth` 继续每次读取父容器 `clientWidth` 与子元素矩形，保证实际可用宽度按当前布局计算。

**等价依据**

缓存的样式值只在头部或父容器尺寸变化、字体变化、缩放变化或文案变化时改变。宽度与子元素矩形仍每次实测，全文与紧凑措辞的判定结果保持一致。

### 2.11 后台轮询等待可见页面

**现状证据**

- `packages/client/src/features/notifications/notifications.ts:81-101` 每 1500 毫秒读取通知激活，未检查页面可见性。
- `packages/client/src/features/home/home-store.ts:140-189` 冷折叠期间每 800 毫秒轮询，未检查页面可见性。
- `packages/client/src/core/page-visibility.ts:8-19` 已提供 `pageHidden()` 与 `subscribePageHidden()`。

**解决方案**

1. 新建 `shared/visibility-gate.ts`，提供单任务等待门。
2. `run(task)` 在页面可见时立即执行；隐藏时保存最新任务，回到可见时执行一次。
3. 连续隐藏期间的多次触发只保留最后一个任务，避免回到前台时补发多次请求。
4. 通知激活轮询的定时回调通过门执行；回到可见时立即补读一次。
5. 首页用量轮询的定时回调通过门执行；回到可见时立即补读一次。
6. 功能停止时释放可见性订阅并清空等待任务。

**等价依据**

可见窗口中的轮询周期和请求内容不变。隐藏窗口不产生网络请求与 JSON 解析。回到可见时补读一次，与现有 `visibilitychange` 唤醒路径一致。通知点击打开会话与首页数据更新时间不变。

### 2.12 指针活动合并到一帧

**现状证据**

- `packages/engine/src/scheduler.ts:202-207` 直接监听 `pointermove`。
- `scheduler.ts:147-150` 每次活动遍历全部功能并调用 `onActivity`。
- `packages/client/src/features/mascot/mascot-player.ts:443-449` 收到活动后只更新 `quietSince` 并按需唤醒。

**解决方案**

1. `pointermove` 处理器只记录“本帧需要派发活动”，并用 `requestFrame` 合并。
2. 帧写入阶段调用一次 `dispatch('onActivity')`。
3. `pointerdown` 与 `keydown` 仍即时派发，保证按下与键入时序不变。
4. 调度器停止时取消未执行的指针活动帧。

**等价依据**

同一帧内的多次移动只把 `quietSince` 更新到该帧的同一时刻。吉祥物 60 秒睡眠阈值对帧内毫秒差没有可见差别。按下与键入仍立即唤醒。

### 2.13 侧栏预览指针判定合并到一帧

**现状证据**

- `packages/client/src/features/sidebar-peek/sidebar-peek.ts:260-263` 每次 `pointermove` 保存坐标并调用 `judge`。
- `sidebar-peek.ts:207-213` 的 `inside()` 每次读取切换按钮和侧栏列的矩形。
- `sidebar-peek.ts:222-234` 的 `judge` 可能设置或清除 300 毫秒离开计时器。

**解决方案**

1. 指针移动只保存最新坐标与按键状态，并请求一帧。
2. 读取阶段计算一次 `inside()` 与 `held()`。
3. 写入阶段用读取结果更新离开计时器。
4. 指针离开窗口与指针移出切换按钮仍由原 `pointerout` 立即处理。
5. 离开计时器到期时仍按原逻辑重新读取当前位置与持有状态。

**等价依据**

同一帧内只判定最后位置。原实现逐事件判定的净结果只由最后位置决定：先移出再移入会清除计时器，先移入再移出会设置计时器。合并后的最后位置产生相同净结果。120 毫秒展开延迟与 300 毫秒收起延迟不变。

### 2.14 调度器维护事件钩子索引

**现状证据**

- `packages/engine/src/scheduler.ts:128-168` 每次派发都遍历全部功能名称并检查钩子方法。
- `scheduler.ts:332-411` 每个调度帧的 `measure` 与 `sync` 也遍历全部功能名称。
- 功能在偏好切换、延迟加载与失败退役时会动态安装和删除。

**解决方案**

1. 在 `SchedulerCalls` 增加 `refreshHandles?: () => void`。
2. 调度器维护每个钩子的句柄数组，以及 `sync` 与 `measure` 的句柄数组。
3. 数组元素保存功能名称与句柄身份，派发时检查 `ui[name] === handle`，防止退役后继续调用。
4. 安装、延迟块到达、偏好切换、退役与释放后，入口调用 `refreshHandles()`。
5. 数组按 `FEATURES` 顺序重建，保持原有调用顺序。
6. `skipOnContentOnly` 仍在每次通过时读取当前句柄，保持动态开关语义。

**等价依据**

索引只消除“该方法是否存在”的重复检查。调用集合、调用顺序、异常隔离与连续失败计数保持不变。句柄身份检查覆盖动态删除与替换。

### 2.15 非 Claude 品牌下等待加载器使用虚拟状态

**现状证据**

- `packages/client/src/features/chat-wait/chat-wait.ts:139-149` 每个等待行都构建三组共 10 个点。
- `chat-wait.ts:180-191` 每个等待行都启动加载器。
- `packages/client/src/features/chat-wait/wait-loader.ts:385-410` 每 10 秒执行一次换场，`pairDots` 最多枚举 256 种配对。
- `packages/client/src/features/chat-wait/chat-wait.css:79-90` 非 Claude 品牌把加载器整体隐藏。

**解决方案**

1. 把加载器状态从 DOM 中解耦：记录创建时刻、当前动作、上一个动作、最近换场时刻与随机选择序列。
2. 非 Claude 品牌下保留虚拟状态与换场计时，不构建点元素，不执行 `pairDots` 与 `poseAt`。
3. 切到 Claude 品牌时构建车道，恢复当前动作；把 CSS 动画的 `startTime` 设为创建时的文档时间线时刻，保持动画相位。
4. 最近换场仍在 300 毫秒过渡窗口内时，重建该次换场并把动画起点设为换场时刻。
5. 切离 Claude 品牌时停止加载器计时并清空车道，保留虚拟状态。
6. 等待行释放时同时释放虚拟状态。

**等价依据**

随机动作序列与换场周期保持不变。Claude 品牌下可见车道、点数、动画相位与进行中的换场按原时刻恢复。非 Claude 品牌下加载器原本不可见，移除点元素与几何计算不改变显示结果。

## 3. 需要单独确认的边界

第 15 项等待加载器在非 Claude 品牌下不再构建 10 个点，也不运行每 10 秒的换场几何计算。常规品牌切换可以按虚拟状态恢复当前车道与动画相位；若切换恰好落在 300 毫秒换场窗口内，旧实现会用换场开始时的几何继续播放，新实现只能用切换时的当前几何重建，二者在极窄的时间窗口内可能差一个像素级位置。该项因此保留为条件任务：未获得对这处边界的明确同意时，只执行第 1 至 14 项，第 15 项不进入零视觉变化验收。

## 4. 不进入本次改造的项目

以下项目仍可能降低开销，但会改变视觉、动画、首屏或交互结果，不能放在“零视觉变化”范围内。

| 项目 | 改动后会改变的结果 |
| --- | --- |
| 消息折叠气泡的整块遮罩 | 叠加渐变在壁纸与半透明画布下露出不同底色 |
| 首页面板的滚动遮罩动画 | 固定遮罩无法复现最后 32 像素的收尾 |
| 运行标题扫光 | 位移伪元素改变文字裁剪与抗锯齿 |

| 首页水波与推理力度点阵 | 降采样或降帧会改变动效手感 |
| 对话功能整体延后加载 | 首次进入会话的首帧会缺少功能 |
| `chat-follow` 的思考行扫描收窄 | 需要新的可见范围判定，当前没有等价证据 |
| `turnNav` 在正文批次中停跑 | 新用户消息会改变回合集合 |
| `composer` 在正文批次中停跑 | 对话根与输入区可能在正文批次中挂载 |
| 行跳过在宽度变化时的整体失效 | 宽度真实变化时必须重新布局，无法等价省略 |
| 搜索面板行节点差分 | DOM 节点身份、焦点与动画重播需要额外证明 |
| 日期分组与进行中优先的增量重排 | 分区标题与行顺序必须逐项证明 |

## 5. 验收方法

### 5.1 单任务验收

每个任务至少通过以下三类检查：

1. 新增逻辑测试或机制测试，先失败，后通过。
2. `npm run build` 通过，确认类型与打包完整。
3. 受影响功能的行为测试、替身页用例或场景通过。

```text
npm run verify -- --only feature:chat-wait
npm run verify -- --only feature:home

npm run verify -- --only feature:workspace
npm run verify -- --only feature:account
npm run verify -- --only case:chat-wait
npm run verify -- --only scenario:waitLine
```

### 5.2 分支验收

全部任务完成后执行：

```text
npm run build
npm run lint
npm run element-collections -- --check

```

### 5.3 性能记录

改动前与全部改动后，在相同机器、相同替身页、相同窗口尺寸下记录：

- `idle-60`
- `thinking-60`
- `typing-1000-200`

记录主线程忙碌时间、长任务数量、p95 帧耗时与调度帧数量。结果写入 `docs/AB-PERFORMANCE.md`，未实测的数字保持待测状态。

至少覆盖浅色与深色、完整动效与减弱动效、Claude 品牌与 DeepSeek 品牌、首页与长会话。对比项包括截图、DOM 属性、动画名称与时长、措辞更换间隔、时钟文本、加载器点数与车道。

## 7. 风险与回退边界

| 风险 | 控制措施 |
| --- | --- |
| 跳过正文批次导致页面功能漏更新 | 仅纳入已有独立订阅的功能；逐功能行为测试；无法证明的功能不进入清单 |
| 缓存未覆盖样式变化 | 缓存与观察器、尺寸订阅或快照身份绑定；无完整失效来源不缓存 |
| 共享尺寸订阅改变回调顺序 | 保留订阅创建顺序；每个订阅每批一次；增加机制测试 |
| 调度器索引遗漏动态安装 | 入口在每个安装、退役与切换点调用 `refreshHandles`；句柄身份检查 |
| 等待行轻量刷新漏掉措辞锁或徽章 | 轻量刷新检查锁到期与超时阈值；没有目标订阅时回退完整同步 |
| 加载器切回品牌时相位变化 | 虚拟状态记录创建与换场时刻；恢复 CSS 动画起始时间 |
| 文件接近停线 | 页脚先拆分固定层模块；过程摘要先拆分宽度缓存模块 |

任何任务若无法同时满足视觉等价与测试通过，停止该任务并保留其余已完成改动，不降低约束强行合并。
