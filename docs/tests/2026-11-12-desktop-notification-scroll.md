# 测试任务：桌面通知与回到底部

- 范围：Windows 桌面端的系统通知，以及读者回到底部后新内容到达时的滚动位置。
- 状态：真实桌面证据待填；本文件记录每项应留存的证据，不把未执行的桌面操作记为通过。
- 前置条件：Windows 10 或 11 桌面端、PowerShell 5.1、系统通知与专注助手设置保持可观察；准备两个以上会话，并准备一段足以滚动到中间的长会话。

## 一、构建、打包与安装

在仓库根目录依次执行：

```powershell
npm run build
npm pack
dsh plugin --profile desktop install .\dsh-claude-style-lite-0.2.3.tgz
```

安装后重启 CodeBuddy。打开插件设置，确认「提示通知窗口」默认开启，并把系统通知权限留在「默认」或「允许」。

## 二、N4 桌面通知

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| N4.1 | Windows 桌面端，开关开启，完成一次顶层会话 | 右下角出现 Toast，标题「任务完成」，正文为会话标题 |
| N4.2 | 查看 Windows 通知中心 | 能找回同一条通知，应用名显示 `CodeBuddy` |
| N4.3 | 点击通知 | 窗口回到前台并切到对应会话 |
| N4.4 | 触发审批、计划审阅、提问 | 三种标题分别出现 |
| N4.5 | 关闭通知开关后再完成一次 | 不产生 Toast，不启动 PowerShell 进程 |
| N4.6 | 保持同一等待状态 | 只有一条通知 |
| N4.7 | Windows 系统通知关闭或专注助手开启 | 插件报告发送失败；界面不崩溃；设置行显示投递失败状态 |
| N4.8 | `dsh web` 打开同一插件 | 使用页面权限与原行为，点击不切会话时只聚焦窗口 |
| N4.9 | 未安装 PowerShell 5.1 | 能力回答 `browser`，页面通道接管 |

## 三、S4 回到底部

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| S4.1 | 长会话滚动到中间，点回到底部 | 一次平滑到末尾，按钮消失 |

| S4.3 | 回到底部后触发工具调用、审批、计划审阅 | 位置始终在末尾 |

| S4.5 | 回到底部后切换会话再切回 | 宿主恢复的记忆位置正确，不额外跳动 |

## 五、判定

- N4 与 S4 的每一行都有截图、录屏或文件观察结果，且「实测记录」写明测试机、时间与结果。
- S4.7 的通过与失败按同一段录屏的连续帧判定，不以「没有看到跳动」代替录屏。
- 通知中心条目以真实系统条目为准，不以页面构造器被调用或私有路由返回 200 代替。
- 点击回会话必须同时观察窗口前台状态与打开的会话标识；只看到窗口抬起不算通过。
- 滚动项以录屏中的连续位置为准；测试记录里不得把「没有看到跳动」写成通过而没有对应录制或截图。
