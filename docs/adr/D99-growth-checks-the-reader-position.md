# D99. 增长写回先判断读者位置

- **取代**：D98

## 背景

读者在长会话里向上翻读，按下宿主的「回到底部」按钮。按钮属于宿主，位于对话滚动容器之外：按钮点击不会产生滚动容器上的读者意图，宿主随后写入末尾也不会产生读者位移。手回的代码已经把读者的持有清掉：`handBackFollow` 调用 `releaseReaderHold(scroller)`，再由 `setHeld(false)` 删除 `held`、`readerPositions`、`readerFloors` 与 `heldTowardEnd`，并撤掉 `READER_HOLD_ATTR`。

新内容到达时，宿主跟随把位置写到末尾；皮肤的 `holdGrowth` 在末尾位置与宿主跟随标记成立时读取 `readerScrollPosition(scroller)!` 并写回。手回之后这个值为 null，非空断言只改变类型，运行时仍把 null 交给 `writeScroll`，`scrollTop = null` 被浏览器解释为 0，读者看到窗口从末尾跳回顶部。

按钮只被点击一次。问题落在增长写回没有判断位置是否仍存在，重复点击与按钮残留都不是这件事的形状。

## 决定

- 增长写回先判断读者位置是否存在。`holdGrowth` 读取 `readerScrollPosition(scroller)`，为 null 时直接返回，本次增长由宿主跟随写末尾。
- 位置存在时，`holdGrowth` 以 `reader` 来源写回该位置；非空断言从这一路径消失。
- `handBackFollow` 继续在点击宿主按钮前调用 `releaseReaderHold(scroller)`，并保持一次请求一次点击的现有确认；`handBackPending` 继续表示交接窗口。
- 读者在按钮点击后再次上滚，`noteIntent` 重新建立持有与位置；此后的增长写回读者自己的位置，这次上滚是位置离开末尾的唯一操作。
- 流式增长的滑动仍按 D95 的合成器位移处理；本次改动只决定增长写回是否发生，不改变滑动开始、时长或抵消对象。

## 后果

- 读者按一次按钮后，宿主写入末尾即是交接完成；后续内容由宿主跟随写末尾，皮肤不再写回旧位置。
- 触屏读者与用滚轮留在上方的读者仍保有写回：读者的位置存在，`holdGrowth` 的写回与之前相同。
- 没有位置的读者不再产生写入；`readerScrollPosition` 的空值在调用处得到判断。
- 放弃的做法：继续用 `handBackPending` 的固定窗口代替位置判断；在按钮点击后按固定时长保留位置；把按钮是否消失当作跟随状态的唯一判据；在内容到达时由皮肤把位置写回旧处。
- 可触发回到底部的入口保持原样：设置页与按钮仍是读者的主动动作；这次改变的是增长何时由皮肤写回。

## 重审条件

- 宿主提供可等待的跟随状态或明确的「已回到底部」事件时，交接的完成条件改为读该事件，删去按钮存在性的确认。
- 宿主提供可替换的滚动跟随策略时，手回与末尾保持交由宿主策略完成（D40）。
- 宿主改变「回到底部」按钮的结构或语义时，重新核对交接入口与完成条件。
