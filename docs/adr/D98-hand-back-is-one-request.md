# D98. 回到底部只发一次请求，只确认一次交接

## 背景

读者向上翻读长会话后按下宿主的「回到底部」按钮。皮肤此前把这个动作实现为轮询：先缓动到末尾，再每隔 100 毫秒找一次按钮，找到就按一次，最多五轮。按钮在按下后并不会立刻从页面消失，宿主的跟随状态要等自己的 500 毫秒滚动采样窗口结束才稳定，于是同一轮交接可能按下多次。只要其中一次落在新内容到达之后，宿主跟随、读者位置写回和按钮触发的跟随就会在同一帧争夺同一个滚动位置，读者看到页面跳到旧处。

这里有两个独立事实需要分开：读者明确要求回到底部，皮肤应当立即释放读者的位置持有；宿主的跟随是否已经恢复，只能由宿主的按钮与跟随状态确认。皮肤没有第二个信号可以判断这件事，重复按按钮也不能替代确认。

## 决定

- 一次回到底部只发一个请求。`handBackFollow` 记录请求代次，取消同一容器的在途手回与缓动；新请求使旧请求失效，旧请求此后不再点击，也不再发起确认。
- 请求发出后立即释放 `READER_HOLD_ATTR`，让宿主跟随接管；释放发生在一次按钮点击之前。
- 位置不在末尾时先滑到末尾；缓动结束后，重新确认按钮仍存在、读者仍需要回到底部，再对宿主按钮发起一次点击。每次请求最多一次按钮点击，确认期间不再点击。
- 点击后只观察，不操作：每 100 毫秒查看按钮是否消失，最多五次；按钮消失或超时都结束这一轮，不补按，也不重开缓动。
- 点击后 500 毫秒内跳过 `chat-follow.ts` 的读者位置写回，这个窗口与宿主滚动采样窗口一致。窗口结束后仍由宿主跟随负责末尾；皮肤不另写一个位置。
- `releaseAtTail` 与结构变化触发的手回共用这个入口，不再各自维护轮询。

## 后果

- 读者按一次按钮只产生一次点击；后续内容到达时位置留在末尾，不再由皮肤把读者位置写回旧处。
- 读者在点击后立刻上滚时，`stillWanted()` 转为 false，本轮结束，读者重新持有位置，按钮再次出现。
- 按钮在缓动期间消失说明宿主已恢复跟随，本轮直接结束；按钮结构变化导致找不到按钮时也视为宿主已接管，不再尝试。
- 完成只靠观察宿主状态，因此确认最多等 500 毫秒；宿主迟迟不隐藏按钮时，这一轮放弃，读者仍可再按一次按钮发起新请求。
- 新增一个手回待确认状态；它必须随请求代次结束而清除，不能跨容器共享。
- 放弃的方案：点击后继续轮询并重复点击，直到按钮消失；点击后继续持有读者位置；用手回结束后的固定延迟代替宿主的跟随状态；在有内容到达时由皮肤把位置写回。
- 可触发回到底部的入口保持原样：设置页与按钮仍是读者的主动动作；这次改变的是交接的次数与顺序。

## 重审条件

- 宿主提供可等待的跟随状态或明确的「已回到底部」事件时，确认改为读该事件，删去按钮存在性的轮询。
- 宿主提供可替换的滚动跟随策略时，手回与末尾保持交由宿主策略完成（D40）。
- 宿主改变「回到底部」按钮的结构或语义时，重新核对一次点击的入口与完成条件。
