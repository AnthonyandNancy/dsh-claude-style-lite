# D99. 宿主回到底部按钮按下即结束读者持有

- **取代**：D98

## 背景

读者在长会话里向上翻读，滚动主人记录了他的意图和位置，并拒绝所有跟随来源。宿主的「回到底部」按钮位于对话滚动容器之外，按钮的点击既不是滚动容器上的读者意图，也不产生读者位移。阅读宿主源码可见，按钮的点击调用 `returnToBottom()`，由宿主自己取消在途动态与导航、调用 `reading.followTail()`，把跟随状态切回并写到末尾。

旧实现里没有一条路径把这次点击告诉滚动主人：持有仍然停在读者离开的位置。宿主随后把位置写到末尾并打开跟随，下一次内容增长时 `holdGrowth` 读到宿主跟随的末尾，按持有写回读者旧位置；此后宿主再次写末尾，再次被写回，窗口就在末尾与旧位置之间来回，读者看到窗口回到顶部。点击本身只发生一次。

滚动主人与宿主各有一套跟随状态时，读者用宿主自己的入口回答跟随，两套状态必须一起结束。

## 决定

- 滚动主人在文档捕获阶段监听宿主「回到底部」按钮的 `click`，该按钮由 `findFollowTailButton` 定位。命中时对会话滚动容器执行 `setHeld(scroller, false)`：删除持有、读者位置与相关记录，撤掉持有标记。
- 监听放在捕获阶段，早于宿主的处理函数：宿主把位置写到末尾与打开跟随之前，持有已经结束，之后的增长只由宿主跟随处理。
- 键盘激活产生同一个 `click`，因此鼠标、触屏与键盘走同一条路径。
- 滚动主人的其余行为恢复成上游实现：手回请求、缓动到末尾、按钮存在性确认与增长写回都保持 `dsh-claude-style` 0.20.3 的写法。皮肤不再用固定的交接窗口改变增长写回。
- 读者在按钮点击后再次滚动，`noteIntent` 重新建立持有与位置；此后的增长写回读者自己的位置。
- 流式增长的滑动仍按 D95 的合成器位移处理；这次改动不改变滑动开始、时长或抵消对象。

## 后果

- 读者按一次按钮，宿主的跟随状态与滚动主人的持有状态一起结束；后续内容由宿主跟随写末尾。
- 触屏读者与用滚轮留在上方的读者仍保有写回：按钮没有被按下，持有与位置都存在，增长写回与上游一致。
- 宿主按钮的结构决定这条路径能否命中。`findFollowTailButton` 找不到按钮时，读者仍可滚回末尾，`releaseAtTail` 照旧交出跟随；这条路径不依赖按钮。
- 放弃的做法：给增长写回加固定时长的交接窗口；把按钮是否消失当作跟随状态的唯一判据；在按钮点击后保留读者位置并继续写回；在增长路径里按位置是否为空来推断读者是否已交出跟随。
- 宿主提供可等待的跟随状态或明确的「已回到底部」事件时，按钮点击监听可以换成读该事件。

## 重审条件

- 宿主改变「回到底部」按钮的结构、位置或语义时，重新核对按钮定位与捕获阶段监听。
- 宿主提供可替换的滚动跟随策略或公开的跟随状态变更事件时，读者交出的判定改为读该状态（D40）。
